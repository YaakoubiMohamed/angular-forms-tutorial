Introduction aux Signals

Les Signals sont une primitive de réactivité introduite dans Angular 16 et stabilisée dans Angular 17+. Ils offrent une alternative plus simple et performante aux Observables RxJS pour la gestion d'état local.

💡 Qu'est-ce qu'un Signal ?

Un Signal est une valeur qui notifie automatiquement les consommateurs intéressés lorsqu'elle change. C'est comme une variable "intelligente" qui sait qui l'observe.

+------------------------------------------------------------------+
|                      SIGNALS ANGULAR                              |
+------------------------------------------------------------------+
|                                                                    |
|   ┌─────────────┐     ┌─────────────┐     ┌─────────────┐        |
|   │  signal()   │────▶│ computed()  │────▶│  effect()   │        |
|   │  Écriture   │     │   Lecture   │     │   Réaction  │        |
|   └─────────────┘     └─────────────┘     └─────────────┘        |

|   │ .set()      │     │ Recalcul    │     │ Exécution   │        |
|   │ .update()   │     │ Automatique │     │ Automatique │        |
|   └─────────────┘     └─────────────┘     └─────────────┘        |
|                                                                    |
+------------------------------------------------------------------+

Avantages des Signals

Avantage Description
🚀 Performance Détection de changement granulaire, permet le mode "Zoneless"
📝 Simplicité API plus simple que RxJS pour l'état local
🔒 Typage Excellent support TypeScript natif
🐛 Débogage Plus facile à tracer et déboguer
🔄 Interopérabilité Fonctionne avec RxJS via toSignal() et toObservable()

type WritableSignal<T>  // Signal modifiable (signal())

Tableau Comparatif

Fonction Type Retourné Usage

signal() - Signal Modifiable

La fonction signal() crée un signal avec une valeur initiale que vous pouvez modifier.

import { signal, WritableSignal } from '@angular/core';

// Création d'un signal
const count: WritableSignal<number> = signal(0);
const name = signal('Jean');  // Type inféré: WritableSignal<string>
const user = signal<User | null>(null);  // Type explicite

// Lecture de la valeur (appeler comme une fonction)
console.log(count());  // 0
console.log(name());   // 'Jean'

// Modification avec .set() - Remplace la valeur
count.set(5);
console.log(count());  // 5

// Modification avec .update() - Basée sur la valeur précédente
count.update(current => current + 1);
console.log(count());  // 6

// Pour les objets/tableaux, utilisez .update() pour l'immutabilité
const users = signal<string[]>([]);
users.update(list => [...list, 'Pierre']);
users.update(list => [...list, 'Marie']);
console.log(users());  // ['Pierre', 'Marie']

Exemple dans un Composant

@Component({
  selector: 'app-counter',
  standalone: true,
  template: `
    <div class="counter">
      <button (click)="decrement()">-</button>
      <span>{{ count() }}</span>
      <button (click)="increment()">+</button>
    </div>
  `
})
export class CounterComponent {
  count = signal(0);

  increment() {
    this.count.update(n => n + 1);
  }

  decrement() {
    this.count.update(n => n - 1);
  }
}

computed() - Signal Dérivé

La fonction computed() crée un signal en lecture seule dont la valeur est automatiquement recalculée lorsque ses dépendances changent.

import { signal, computed, Signal } from '@angular/core';

const firstName = signal('Jean');
const lastName = signal('Dupont');

// Signal computed - recalculé automatiquement
const fullName: Signal<string> = computed(() => {
  return `${firstName()} ${lastName()}`;
});

console.log(fullName());  // 'Jean Dupont'

// Quand une dépendance change, le computed se recalcule
firstName.set('Pierre');
console.log(fullName());  // 'Pierre Dupont'

Computed avec Conditions

const price = signal(100);
const quantity = signal(2);
const discount = signal(0.1);  // 10%

const subtotal = computed(() => price() * quantity());
const discountAmount = computed(() => subtotal() * discount());
const total = computed(() => subtotal() - discountAmount());

console.log(total());  // 180 (200 - 20)

// Changement de quantité
quantity.set(3);
console.log(total());  // 270 (300 - 30) - Tout est recalculé!

Computed pour l'État du Formulaire

@Component({
  template: `
    <form [formGroup]="form">
      <input formControlName="email">
      <input formControlName="password" type="password">
      
      <div class="status">
        <span [class.valid]="formValid()">
          {{ formValid() ? '✓ Valide' : '✗ Invalide' }}
        </span>
        <span>Champs remplis: {{ filledFieldsCount() }}/2</span>
      </div>
      
      <button [disabled]="!formValid()">Soumettre</button>
    </form>
  `
})
export class LoginFormComponent {
  form = new FormGroup({
    email: new FormControl('', [Validators.required, Validators.email]),
    password: new FormControl('', [Validators.required, Validators.minLength(8)])
  });

  // Computed signals pour l'état du formulaire
  formValid = computed(() => this.form.valid);
  
  filledFieldsCount = computed(() => {
    let count = 0;
    if (this.form.get('email')?.value) count++;
    if (this.form.get('password')?.value) count++;
    return count;
  });
}

effect() - Effets de Bord

La fonction effect() exécute une fonction chaque fois que les signals qu'elle lit changent. Utile pour le logging, la synchronisation avec le localStorage, ou les appels API.

import { signal, effect } from '@angular/core';

const user = signal<User | null>(null);
const theme = signal('light');

// Effect pour le logging
effect(() => {
  console.log('Utilisateur actuel:', user());
});

// Effect pour synchroniser avec localStorage
effect(() => {
  localStorage.setItem('theme', theme());
  document.body.className = theme();
});

// Les effects se déclenchent automatiquement quand les signals changent
user.set({ name: 'Jean', email: 'jean@example.com' });
// Console: 'Utilisateur actuel: { name: "Jean", email: "jean@example.com" }'
⚠️ Attention

Les effects doivent être créés dans un contexte d'injection (constructeur ou avec inject()). Évitez de modifier des signals dans un effect pour prévenir les boucles infinies.

Effect avec Cleanup

@Component({...})
export class TimerComponent {
  seconds = signal(0);
  isRunning = signal(false);

  constructor() {
    // Effect avec fonction de nettoyage
    effect((onCleanup) => {
      if (this.isRunning()) {
        const interval = setInterval(() => {
          this.seconds.update(s => s + 1);
        }, 1000);

        // Nettoyage quand l'effect se ré-exécute ou le composant est détruit
        onCleanup(() => clearInterval(interval));
      }
    });
  }

  toggle() {
    this.isRunning.update(r => !r);
  }
}

Effect pour Debug de Formulaire

@Component({...})
export class DebugFormComponent {
  submitted = signal(false);
  submittedData = signal<any>(null);

  constructor() {
    // Log automatique quand le formulaire est soumis
    effect(() => {
      const data = this.submittedData();
      if (data) {
        console.log('📧 Formulaire soumis:', data);
        console.log('📅 Timestamp:', new Date().toISOString());
      }
    });
  }

  onSubmit(formValue: any) {
    this.submitted.set(true);
    this.submittedData.set(formValue);
  }
}

toSignal() - Conversion Observable → Signal

La fonction toSignal() convertit un Observable RxJS en Signal. C'est particulièrement utile pour intégrer les Signals avec les formulaires réactifs.

import { toSignal } from '@angular/core/rxjs-interop';
import { FormControl } from '@angular/forms';

const email = new FormControl('');

// Convertir valueChanges en Signal
const emailValue = toSignal(email.valueChanges, { initialValue: '' });
const emailStatus = toSignal(email.statusChanges, { initialValue: 'VALID' });

// Utilisation dans le template
console.log(emailValue());  // Valeur actuelle
console.log(emailStatus()); // 'VALID', 'INVALID', 'PENDING'

Options de toSignal()

Option Description
initialValue Valeur initiale avant la première émission
requireSync Force une valeur synchrone (erreur si pas disponible)
manualCleanup Désactive le nettoyage automatique 
// Sans initialValue - le type inclut undefined
const value1 = toSignal(observable$);
// Type: Signal<T | undefined>

// Avec initialValue - type exact
const value2 = toSignal(observable$, { initialValue: 0 });
// Type: Signal<T>

// Pour les BehaviorSubject (valeur synchrone garantie)
const value3 = toSignal(behaviorSubject$, { requireSync: true });
// Type: Signal<T>

toObservable() - Conversion Signal → Observable

import { toObservable } from '@angular/core/rxjs-interop';

const count = signal(0);

// Convertir Signal en Observable
const count$ = toObservable(count);

// Utiliser avec les opérateurs RxJS
count$.pipe(
  filter(n => n > 0),
  debounceTime(300)
).subscribe(value => {
  this.saveToServer(value);
});

Intégration avec les Formulaires Réactifs

Voici un exemple complet d'intégration des Signals avec les Reactive Forms d'Angular.

import { Component, signal, computed, effect } from '@angular/core';
import { FormBuilder, FormGroup, Validators, ReactiveFormsModule } from '@angular/forms';
import { toSignal } from '@angular/core/rxjs-interop';

@Component({
  selector: 'app-registration',
  standalone: true,
  imports: [ReactiveFormsModule],
  template: `
    <form [formGroup]="form" (ngSubmit)="onSubmit()">
      <!-- Champs du formulaire -->
      <input formControlName="email" placeholder="Email">
      <input formControlName="password" type="password" placeholder="Mot de passe">
      
      <!-- État avec Signals -->
      <div class="form-status">
        <span>Valide: {{ formValid() }}</span>
        <span>Modifié: {{ formDirty() }}</span>
        <span>Status: {{ formStatus() }}</span>
      </div>
      
      <!-- Erreur de soumission -->
      @if (submitError()) {
        <div class="error">{{ submitError() }}</div>
      }
      
      <!-- Succès -->
      @if (submitted() && !submitError()) {
        <div class="success">Formulaire soumis avec succès!</div>
      }
      
      <button type="submit" [disabled]="!canSubmit()">
        {{ isLoading() ? 'Envoi...' : 'Soumettre' }}
      </button>
    </form>
  `
})
export class RegistrationComponent {
  // Formulaire réactif
  form: FormGroup;

  // ===== WRITABLE SIGNALS (état modifiable) =====
  submitted = signal(false);
  submitError = signal<string | null>(null);
  isLoading = signal(false);

  // ===== SIGNALS DÉRIVÉS DES OBSERVABLES =====
  formValue: Signal<any>;
  formStatus: Signal<string | undefined>;

  // ===== COMPUTED SIGNALS (état dérivé) =====
  formValid = computed(() => this.form.valid);
  formDirty = computed(() => this.form.dirty);
  
  canSubmit = computed(() => {
    return this.formValid() && !this.isLoading() && !this.submitted();
  });

  constructor(private fb: FormBuilder) {
    this.form = this.fb.group({
      email: ['', [Validators.required, Validators.email]],
      password: ['', [Validators.required, Validators.minLength(8)]]
    });

    // Convertir les Observables en Signals
    this.formValue = toSignal(this.form.valueChanges, { 
      initialValue: this.form.value 
    });
    this.formStatus = toSignal(this.form.statusChanges, { 
      initialValue: this.form.status 
    });

    // Effect pour le logging
    effect(() => {
      if (this.submitted() && !this.submitError()) {
        console.log('✅ Données soumises:', this.formValue());
      }
    });
  }

  async onSubmit() {
    if (!this.form.valid) return;

    this.isLoading.set(true);
    this.submitError.set(null);

    try {
      // Simuler un appel API
      await this.fakeApiCall(this.form.value);
      this.submitted.set(true);
    } catch (error) {
      this.submitError.set('Erreur lors de la soumission');
    } finally {
      this.isLoading.set(false);
    }
  }

  private fakeApiCall(data: any): Promise<void> {
    return new Promise((resolve) => setTimeout(resolve, 1000));
  }
}

Toggle Password Visibility

@Component({
  template: `
    <div class="password-field">
      <input 
        [type]="showPassword() ? 'text' : 'password'"
        formControlName="password"
        placeholder="Mot de passe">
      <button 
        type="button" 
        (click)="togglePassword()"
        [attr.aria-label]="showPassword() ? 'Masquer' : 'Afficher'">
        {{ showPassword() ? '🙈' : '👁️' }}
      </button>
    </div>
  `
})
export class PasswordFieldComponent {
  showPassword = signal(false);

  togglePassword() {
    this.showPassword.update(show => !show);
  }
}

Compteur d'Emails Dynamique (FormArray)

@Component({
  template: `
    <fieldset>
      <legend>Emails ({{ emailCount() }})</legend>
      
      @for (email of emailsArray.controls; track $index) {
        <div class="email-row">
          <input [formControl]="$any(email)" placeholder="Email">
          <button type="button" (click)="removeEmail($index)">❌</button>
        </div>
      }
      
      <button type="button" (click)="addEmail()" [disabled]="!canAddMore()">
        ➕ Ajouter ({{ remainingSlots() }} restants)
      </button>
    </fieldset>
  `
})
export class DynamicEmailsComponent {
  form = new FormGroup({
    emails: new FormArray([])
  });

  maxEmails = 5;

  // Computed signals
  emailCount = computed(() => this.emailsArray.length);
  canAddMore = computed(() => this.emailCount() < this.maxEmails);
  remainingSlots = computed(() => this.maxEmails - this.emailCount());

  get emailsArray(): FormArray {
    return this.form.get('emails') as FormArray;
  }

  addEmail() {
    if (this.canAddMore()) {
      this.emailsArray.push(new FormControl('', [Validators.required, Validators.email]));
    }
  }

  removeEmail(index: number) {
    this.emailsArray.removeAt(index);
  }
}

Validation Progress Bar

@Component({
  template: `
    <form [formGroup]="form">
      <div class="progress-bar">
        <div class="progress" [style.width.%]="validationProgress()"></div>
      </div>
      <p>{{ validationProgress() }}% complété</p>
      
      <input formControlName="name" placeholder="Nom">
      <input formControlName="email" placeholder="Email">
      <input formControlName="phone" placeholder="Téléphone">
      <textarea formControlName="message" placeholder="Message"></textarea>
    </form>
  `,
  styles: [`
    .progress-bar { height: 8px; background: #e0e0e0; border-radius: 4px; }
    .progress { height: 100%; background: #4caf50; transition: width 0.3s; }
  `]
})
export class ProgressFormComponent {
  form = new FormGroup({
    name: new FormControl('', Validators.required),
    email: new FormControl('', [Validators.required, Validators.email]),
    phone: new FormControl(''),
    message: new FormControl('', Validators.required)
  });

  validationProgress = computed(() => {
    const controls = Object.values(this.form.controls);
    const validCount = controls.filter(c => c.valid).length;
    return Math.round((validCount / controls.length) * 100);
  });
}

Bonnes Pratiques

✅ À Faire

  • Utiliser signal() pour l'état local du composant
  • Utiliser computed() pour les valeurs dérivées
  • Utiliser toSignal() pour les valueChanges et statusChanges
  • Typer explicitement vos signals quand nécessaire
  • Utiliser .update() plutôt que .set() quand la nouvelle valeur dépend de l'ancienne

❌ À Éviter

  • Modifier des signals dans un effect() (risque de boucle infinie)
  • Créer des effect() en dehors d'un contexte d'injection
  • Oublier d'appeler le signal comme une fonction: count() et non count
  • Utiliser des Signals pour des flux de données complexes (préférer RxJS)

Quand Utiliser Signals vs RxJS

Cas d'Usage Signals RxJS
État local du composant ✅ Recommandé Possible
État du formulaire ✅ Avec toSignal() ✅ valueChanges
Appels HTTP ❌ ✅ Recommandé
WebSocket, événements ❌ ✅ Recommandé
Transformations complexes ❌ ✅ Opérateurs RxJS
UI réactive simple ✅ Recommandé Overkill
